# ExamFlow 平台升级运行手册

## 1. 配置与启动前置

复制根目录 `.env.example` 为本地环境配置，并至少设置：

- `EXAM_DB_PASSWORD`：PostgreSQL 密码；需要时同步设置数据库地址、端口和名称。
- `REDIS_STACK_HOST`、`REDIS_STACK_PORT`、`REDIS_STACK_PASSWORD`：Redis Stack 连接信息。
- `ZHIPUAI_API_KEY`：重排与质量评估模型密钥；不配置时助手仍可使用本地 Ollama，但会走基础质量兜底。
- `OLLAMA_BASE_URL`：本地模型地址。

不要把真实密钥提交到仓库。历史环境中出现过的密钥应在服务商控制台立即轮换。

## 2. 数据库迁移

在 `new-exam` 数据库执行 `sql/migration_2026-08-25_platform_upgrade.sql`。脚本包含：

- 在线答题恢复索引；
- Agent 运行、步骤、反馈表；
- 知识文档、知识切片、PGVector 表及 HNSW 索引；
- 监考进出场事件表。

生产环境应由 Flyway/Liquibase 或发布流水线执行迁移，并在执行前备份数据库。

## 3. 核心业务验收

1. 教师创建考试、设置开始时间/时长/人数/及格分，并配置题目 ID。
2. 学生报名，在考试准备页完成摄像头校验后进入考试。
3. 每次切题答案自动保存；刷新或短暂断线后可从服务端恢复；交卷空请求也会使用服务端答案兜底。
4. 客观题自动判分，主观题在“主观题阅卷”页面评分，全部主观题完成后成绩状态变为已批改。
5. 教师在监考大屏输入考试 ID，查看实时画面和最近监考事件。

## 4. 错题助手验收

- 学生从“错题助手”选择错题并追问；服务会执行错题上下文构建、混合检索、重排、答案生成和质量评估。
- 质量不通过最多重试 3 次，最终返回可解释的兜底结果；运行信息写入 `ai_agent_run/ai_agent_step`。
- 教师在“错题知识库”粘贴课程资料入库，系统自动切片并写入 PGVector、Redis Stack 和兼容降级表。
- 学生可以对回答标记“有帮助/需改进”，反馈写入 `ai_answer_feedback`。

## 5. 运维检查

- AI 服务健康检查：`/ai/actuator/health`。
- 考试服务健康检查：`/exam/actuator/health`。
- 重点指标：AI 回答耗时、质量通过率、重试次数、PG/Redis 检索失败率、自动交卷失败率、监考连接异常数。
- 先启动认证、数据库/Redis、服务发现，再启动业务服务和网关，最后启动前端。
